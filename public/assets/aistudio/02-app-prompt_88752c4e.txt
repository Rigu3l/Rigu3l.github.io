# THE PAGE SHEET: STRUCTURE
=====================================================================
<div class="content" id="content">
  <section id="about">      greeting + intro + what I do
  <section id="numbers">    sticky stats band that opens with a clip-path and runs horizontally, then fades into the mesh gradient
  <section id="work">       works tunnel (pinned) + phone / social section
  <section id="contact">    contact links + brief form + footer word
</div>

Look: Swiss-editorial. A 12-column grid (max width ~1600 px, gutters 24 px on desktop, 20 px on phones). A single thin vertical rule runs after column 4 on desktop; the greeting and labels sit in the narrow left zone, the large body text in the wide right zone. Hairlines in --line. Tiny mono micro-labels (JetBrains Mono, uppercase, letter-spacing .06em) for indices like "(01) About". Large type in the display face, body in Inter. The sheet has a rounded top (radius ~28-40 px), a soft upward shadow, and a --paper background. Every block has generous vertical rhythm (clamp(80px, 12vw, 200px)).

Rising over the room: the sheet begins to peek ~10% at the end shot of the story and then slides up until it fully covers the canvas (Part 1 hides the canvas and pauses rendering at that moment).

=====================================================================
# 1. ABOUT / GREETING
=====================================================================
- A pinned greeting in the left zone (position: sticky) showing a small portrait (my own photo or an abstract placeholder), a greeting line ("Hi, I'm <name>") and my role / location. It stays while the right zone scrolls past
- Right zone: a giant statement paragraph in the display or heavy Inter face, revealed word by word (see the reveal engine), followed by 2-3 body paragraphs and a "what I do" list: each item with an index number, a title, one line and a hairline between rows
- A small link row below (e.g. "Selected work", "Contact") using the arrow icons from the SVG sprite (never text arrows)
- All text comes from the dictionaries via data-i18n

=====================================================================
# 2. REVEAL ENGINE (content.js)
=====================================================================
One IntersectionObserver (+ a scroll-linked path where needed) drives all reveals; no GSAP, no scroll libraries.
- WORD-SPLIT BLUR REVEAL: elements with data-reveal="words" are split into per-word spans (preserve whitespace, preserve inline links / <br>, re-split on language change). Each word starts at opacity 0, translateY(.35em), filter blur(10px) and transitions to clear with a stagger of 22 ms per word (cap total at ~700 ms). Use will-change only while animating. Reduced motion: no blur / translate, just a quick fade
- LINE MASKS: block headings can use overflow:hidden lines that rise from translateY(110%) like the wall headlines
- COUNTERS: data-count="N" with data-suffix / data-prefix; count from 0 with an ease-out over ~1.6 s when 60% visible, using tabular-nums so width does not jump; respect locale number formatting; under reduced motion show the final value at once
- KINETIC DRIFTING LINES: a few oversized lines of display text (one per row, alternating direction) that drift horizontally with scroll (translateX = scrollProgress * +-12vw), set with a single rAF-throttled scroll handler writing CSS variables, never layout properties
- FADE-UP for generic blocks (opacity + 24 px translate, 700 ms)
- Everything is idempotent (a re-run after a language change or resize must not double-wrap)

=====================================================================
# 3. NUMBERS BAND
=====================================================================
- A tall section (~300vh) containing a sticky stage (100vh). Scroll progress inside the section drives everything (compute it from the section's rect each frame, via the shared rAF loop):
  a) OPEN (0-.25): the stage's background is revealed through clip-path: inset(Y% X% round R) animating to inset(0) (a rounded window grows to full bleed); the background is a deep --ink navy
  b) RUN (.25-.85): a wide row of stat cards / big numbers translates horizontally (translateX from 0 to -(rowWidth - viewportWidth)), each number is large display type with the light-text gradient, a mono label under it, hairline dividers. Counters trigger as each enters the viewport centre. On phones: the row becomes a vertical stack of stats within the sticky stage (simple fade/slide) because horizontal scroll-jacking is hostile on touch
  c) FADE (.85-1): the stage fades to a flat navy that continues straight into the mesh gradient block, so there is no visible seam
- Header uses .on-color while the stage is dark so the mix-blend-mode difference header remains legible
- setBarColor(navy) while this band is under the browser bar on phones

=====================================================================
# 4. WEBGL MESH GRADIENT (mesh.js)
=====================================================================
- Own <canvas> and own WebGLRenderer (or raw WebGL), full width, ~100vh tall, inside a section that follows the numbers band. Renders only while visible (IntersectionObserver) and pauses when the tab is hidden
- Fragment shader: 5 coloured blobs (my palette's gradient hues) orbiting on sin/cos paths with slightly different speeds; domain warping (2 passes of low-frequency noise offsets to the UVs, amplitude ~0.15); smooth blend by inverse-distance weights; a gentle vignette; ORDERED DITHER (Bayer 4x4 or blue-noise-ish hash, +-0.5/255) to kill banding; output sRGB
- Render at 1/3 resolution (CSS-scaled up with image-rendering default smoothing) because it is a soft blur anyway; cap the frame rate to 30 fps on phones
- Over the gradient, a short statement or a call to action in large display type (my words), with the light-text gradient. The top of the block continues the navy of the numbers band; the bottom blends to --paper or to the next dark block
- Fallback: if WebGL fails, a CSS multi-radial-gradient background with a slow keyframe drift. Reduced motion: render one static frame

=====================================================================
# 5. WORKS TUNNEL (works.js)
=====================================================================
- A pinned section (~400-600vh depending on the number of works) with a sticky 100vh stage and its own WebGL canvas
- Concept: the project cards are placed on a SPIRAL / helix along the z axis (each card rotated and offset around the tunnel axis), and the camera flies forward along the axis as the visitor scrolls, so cards stream past like walls of a tunnel. Cards are planes with rounded-corner alpha masks, showing the cover image (or a short video loop via VideoTexture for those that have one)
- Chapters / stations: works are grouped by chapter name; the camera eases to a stop at each chapter ("station") so the current card faces the viewer, then continues. Show a small HUD: chapter label, project title, year and role (real HTML, bottom-left), a counter "03 / 10", and a dot nav on the right (click a dot to scroll to that station). The current project's title links to its URL (opens in a new tab with rel="noopener")
- Zoom-blur post shader: a full-screen pass that applies a radial blur from the centre whose strength follows the camera's speed (scroll velocity, smoothed), plus a little chromatic split; this sells the flying feel and hides texture pop-in
- Circular opening: when the section enters, the stage is revealed through a circular clip (clip-path: circle(r at 50% 50%) from 0 to 150%) tied to scroll progress, and mirrored on exit
- Loading: use ImageBitmapLoader (createImageBitmap) with colorSpace sRGB, decode off the main thread; lazy-load the covers nearest the camera first and upload one texture per frame to avoid hitches; videos play only when their card is near the camera and pause otherwise
- Dispose of textures that are far behind the camera on phones (keep a window of ~6 cards)
- Accessibility: all works are also present as a real, visually-hidden <ol> list of links with titles and descriptions; a "view as list" toggle shows a plain responsive grid of cards (also the fallback for reduced motion, no WebGL, and for ?nostory). Keyboard: Arrow keys / Tab move between stations
- Phones: fewer cards drawn (window of ~5), no zoom-blur, DPR capped at 1.5, vertical swipe works natively because scroll drives the camera

=====================================================================
# 6. THE 3D PHONE (ig-phone.js)
=====================================================================
- A section after the works: a headline (my words, e.g. about what I post / share) next to or above a 3D phone rendered in its own small WebGL canvas (lazy; created when within ~1 viewport, disposed or paused when far)
- The phone: an extruded rounded-rectangle frame (ExtrudeGeometry with bevel, dark metal PBR), a screen plane with a canvas texture, a notch / dynamic-island pill, subtle reflections from a RoomEnvironment
- The screen texture is an infinite vertical FEED I draw in a 2D canvas (e.g. 540x1170): status bar, a header, then stacked post cards (avatar, name, image area filled with the post image or gradient, caption, action icons drawn as simple vector shapes). My OWN generic social UI, no real brand logos or names. The feed scrolls by offsetting the draw (animated slowly and also driven by page scroll). Re-upload the texture only when the offset changes by >= 1 px; use needsUpdate sparingly (throttle to 30 fps)
- FLOATING POSTS: 3-4 post cards (planes with rounded masks and drop shadows) orbit / float around the phone at different depths, bobbing on sin waves, parallaxing opposite to the phone
- TILT: the phone eases toward the pointer (rotateY / rotateX up to ~14 deg, spring) on fine pointers; on touch devices the tilt is driven by scroll progress (a gentle -12 to +12 deg sweep). Smooth with 1 - exp(-dt * 5)
- Phone browser-bar tint: when this section sits under the browser's bottom bar, call setBarColor with the section's background colour (sample it from CSS custom properties, not from pixels)
- Reduced motion: static tilt, no floating

# 7. CONTACT AND THE BRIEF FORM (content.js)
=====================================================================

Each row: big text, an arrow icon from the sprite, a hairline, and a HOVER FILL: a background layer (accent) that scales up from the bottom (transform: scaleY(0 -> 1), transform-origin bottom, 350 ms cubic-bezier(.2,.8,.2,1)) while the text colour flips to --paper; on touch, a short :active version. Fit-lines: each text input is a single line of big text whose font-size shrinks (down to 60%) so the content always fits the width without wrapping or horizontal scroll; re-fit on input and on resize (use canvas measureText or a hidden measuring span, rAF-throttled)

Disable the button, show a "Sending..." label; on success show a thank-you state in the card (and aria-live), reset the form; on network error or non-2xx, FALL BACK to a mailto: link built with encodeURIComponent (subject and body from the fields, truncated to ~1800 chars) and tell the user plainly what happened. Never lose the user's input
- Provide an optional serverless stub at api/brief (Node / edge function, validates input, length limits, simple rate-limit hint, forwards to an email service via an environment variable; commented, with NO secrets in the repo). If I say there is no backend, ship only the mailto fallback and a README note

=====================================================================
# 8. FOOTER WORD (content.js)
=====================================================================
- A giant word / short phrase at the bottom of the page, display face, full-width (font-size set from the container width so it spans edge to edge), light-text gradient on the dark navy footer
- Each letter is its own inline span containing an SVG-filtered layer: an inline <svg> with <filter id="warp-N"> using feTurbulence (baseFrequency ~0.012 0.02, numOctaves 2) feeding feDisplacementMap (scale animating 0 -> ~40 on hover / pointer proximity). Per-letter: scale = f(distance from the pointer to the letter's centre), eased (lerp .12), so letters near the cursor ripple and bend while the rest stay crisp; they relax when the pointer leaves. Animate the turbulence seed or baseFrequency slowly for a liquid feel
- Performance guard: filters on huge text are expensive. Only enable while the footer is in view, only update the letters whose value changed by > 0.5, drop to a CSS translate / skew wobble per letter on phones and on browsers where the filter is slow (detect via a quick frame-time probe), and disable under reduced motion
- Below the word: small mono credits row (copyright year computed in JS, "Built with care", a back-to-top link with an up arrow icon)

=====================================================================
# 9. THE VOXEL 3D CURSOR AND CURSOR-HINT PILL (cursor.js)
=====================================================================
(fine pointers only; none on touch)
- A tiny dedicated transparent canvas (about 96x96 CSS px, fixed, pointer-events none, z-index above everything) following the pointer with a spring (k = 1 - exp(-dt * 18)). Inside: a small VOXEL arrow cursor assembled from ~20-30 cubes (InstancedMesh of RoundedBoxGeometry) in an arrow silhouette, accent-coloured with a lighter edge, lit by one key light + hemisphere; it leans toward its velocity (rotation.z / rotation.y from clamped vx, vy) and squashes slightly on press. Only renders while moving (stop the loop ~300 ms after the pointer stops) to save power
- Contextual states set by data-cursor on elements: "link" (cubes expand slightly, arrow becomes a hand-like pointer shape), "drag" (the grab hand, used for the plug in Part 1), "view" (a labelled pill), "text" (a thin bar). The native cursor is hidden only where the voxel cursor is active, and restored if WebGL fails (then do NOT hide the native cursor)
- CURSOR-HINT PILL: a small label pill that trails the cursor on a spring (offset +26, +14), shown for elements with data-hint="..." (e.g. "Drag to explore", "Click to open", "Hold to update" from Part 1). It scales .8 -> 1 on appear, tilts with speed (rotateY from vx * .03 capped 28 deg, rotateX from -vy * .03 capped 22, rotateZ vx * .008 capped 10) and is hidden on touch and under reduced motion
- Reuse / reconcile with the cursor pill in Part 1's os.js (one shared pill component; do not duplicate)
