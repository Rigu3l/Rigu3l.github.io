### 2b. CRT tube shader
- uv = .5 + c * (1 + .09 * dot(c,c) * 4) * .94 where c = vUv - .5 (convex bulge toward the viewer). Outside 0..1 = black
- Scanlines: 1 - .1 * (.5 - .5 * cos(uv.y * 1080 * PI)). FADE THEM OUT when fwidth(uv.y) * 1080 shows the screen is drawn too small to resolve them (otherwise they alias into moving stripes on phones)
- Soft dark corners: mix(.55, 1, smoothstep(.75, .3, length(c * vec2(1, 1.15)))). Final colour multiplied by a "power" uniform. toneMapped:false, fog:false
- Modern screen texture (on SCREEN_modern, basic material): a 1600x900 canvas, radial gradient from an accent glow at the bottom centre to the dark base, 6 faint concentric ellipse arcs at 8% alpha, the logo centred at 90%, a dock-like rounded strip with 6 small coloured rounded squares

### 2c. The "connect" screen (connect-screen.js)
- A LOW-RES 360x270 canvas redrawn on demand, then copied into a 1440x1080 canvas (x4) with imageSmoothingEnabled=false. Every icon, cable and glyph is crisp square pixels. This is the screen's texture until the connection is made
- Sprites are ASCII maps (one char per pixel, scaled x3): a small device (~22x18), a target icon such as a globe (~20x17), and a 9x5 plug. DESIGN MY OWN sprites that fit my story (they must not resemble the originals)
- A thin, tall bitmap font (6x11-cell glyphs, 1-pixel strokes) drawn at full resolution with its own pixel size for two caption lines (a prompt in my words, in both languages). The captions are drawn once into a cached layer and only stamped each frame. Draw my own glyph set for exactly the letters I need
- Layout constants in low-res px: the device, the cable's port on the device, the target icon, a socket beside the target, and a "rest" position where the plug hangs before it is taken
- The cable is a quadratic Bezier from the port to the plug, drawn with 2x2 pixel dots (sag 26 - near*14 while dragging; 6 when connected)
- States: target icon dim, then brighter when the plug is near (< 75 px), then bright/filled when done. A pulsing pixel ring around the target when near. An installer-style dotted arrow between device and target while not done (brightens when near). The device screen turns accent-blue when done. Data pixels travel along the cable when done
- Skip the redraw AND the GPU upload when nothing visibly changed (key = rounded plug position + near thresholds)

### 2d. The interaction
- The user drags the plug (mouse or finger). Hit-test by raycasting the pointer against the screen mesh and mapping the UV back through the SAME barrel distortion as the CRT shader, so the plug follows the pointer exactly. Fingers get a 1.8x hit area. The system cursor becomes a hand over the plug, and a grabbing hand while dragging
- Connect when within 18 px of the socket. Releasing within 45 px magnets it in. Releasing farther springs back to the hook (lerp 0.2 per frame). Keyboard: Enter / Space slides the plug in over 500 ms
- On connect: click SFX, start SFX 180 ms later, start the music (this gesture unlocks audio), and after 1.1 s the tube flickers (power uniform drops to 0.05 then ramps back over ~650 ms). Swap the texture to the first story screen while it is dark, re-frame the camera, then add body.entered
- Deep links (#about, #numbers, #work, #contact) skip the whole story: mark every gate done, add body.entered, and scrollIntoView the block

## 4. STORY TIMELINE (vh; one constants table)
Let p1 = clamp(pv / 200). ease = cubic in-out. range(x, a, b) = clamp((x - a) / (b - a)).
1. PULL BACK (0-200). Camera lerps from a CLOSE shot to the WIDE shot with ease(range(p1, .12, .66)). FOV lerps too.
   - CLOSE framing: distance d = max(screenSize.y / .78, screenSize.x / (.9 * aspect)) / (2 * tan(fov / 2)), fov ~38. On narrow phones (aspect < .8) fit the width at 1.28x (1.08x while the connect screen is up) and shift the camera x by -0.062 * screenSize.x
   - WIDE shot: position (0, 1.36, 1.62), target (0, 1.22, -1.3), horizontal FOV 62 deg converted to vertical, at least 35 deg vertical on landscape, max 74. Phones (portrait) use a closer pose (0, 1.32, 1.28) to (0, 1.13, -1.45) and an 82 deg horizontal FOV
   - Mouse parallax (fine pointers only): camera x += mouse.x * .22 * k, y -= mouse.y * .10 * k, target x += .05, y -= .03, plus a hint of roll (-mouse.x * .008 * k), where k = (.35 + .65 * t) * (1 - .9 * pushZ). Smooth the mouse: lerp factor 1 - exp(-dt * 2.6)
2. CARDBOARD-TO-REAL REVEAL (cardboardify shader). At the start everything except the hero object is plain kraft cardboard. A radius uReveal grows 0 to 3.2 m from the hero object over p1 .42-.9; the boundary is torn and fibrous (edge = (cardTex.r - .55) * .5 added to the distance). Patch the standard material with onBeforeCompile: mix diffuseColor with the cardboard; roughness to 1; metalness to 0; kill emissive in the cardboard part. Leave a 10% cardboard memory in the finished room (uCardFloor = .1 * ease(range(p1, .7, .95)))
3. FIRST WALL HEADLINE: in at ease(range(p1, .6, .76)), out at ease(range(pv, 225, 255)) (see section 5)
4. MODERNISATION (pv 245-425). mod = range(pv, 245, 425).
   - Wave A: a cardboard circle scales out from the hero object over the OLD room. waveA = lerp(-.2, 3.4, ease(range(mod, .02, .46)))
   - At mod .5 the eras swap: old meshes are pushed off-screen in the vertex shader (cardWp.xyz = (0,-50,0) when uMod >= .5), new ones brought in (when uMod < .5)
   - Wave B: the living new room scales out the same way. waveB = lerp(-.2, 3.4, ease(range(mod, .54, .98))), inactive (-1) before mod .54
   - Fragment: wd = distance(worldPos, centre) + (cardTex.r - .55) * .5; cardMix = max(cardMix, (1 - smoothstep(waveA - .12, waveA + .12, wd)) * smoothstep(waveB - .12, waveB + .12, wd))
   - Lighting grade k = ease(range(mod, .05, .9)): lamp colour warm to cold white-blue, intensity 3.4 to 2.2, lamp position and target lerp between old and new lamp positions, spot angle .95 to 1.15, hemisphere colour and intensity, LED strip intensity 10 * ease(range(mod, .35, .8)), film `warm` = 1 - k, dust tint
   - Hide the old CRT glass early (visible only while mod < .1). CRT power = (1 - .25 * firstTextIn) * (1 - range(mod, .04, .1)) * flicker
   - Visibility: old era visible while mod < .5, new after. Re-bake shadows once when the era flips (castShadow follows the active era). Fade AO instead of toggling it
5. SECOND WALL HEADLINE: in ease(range(pv, 430, 470)), out ease(range(pv, 500, 522)), placed above the MODERN monitor
6. PUSH INTO THE MODERN SCREEN: pushZ = ease(range(pv, 510, 575)) * (1 - ease(range(pv, exitStart, exitEnd))). Camera and target lerp to CLOSE_M, FOV 30. CLOSE_M distance: landscape d = max(msSize.y / .94, msSize.x / (.96 * aspect)) / t; portrait d = (msSize.x / 2.3 / aspect) / t (the middle ~700 design px of the panel fill the phone width)

- On start: click SFX, riser.start(h / STAGES) so the build-up continues from the current progress, and smooth-scroll to the gate position if the page isn't there yet
- Each frame (use REAL elapsed time, clamped to 0.25 s, because the render loop clamps its own dt): if holding, h += dt / STAGE_SEC; if released, spring back to the START OF THE CURRENT STAGE: h = max(floor(h), h - dt * 1.6). At h >= STAGES: stop riser, done, start SFX, smooth-scroll to gate.next
- A quick click (< 450 ms) shows the tip "KEEP HOLDING" on the button for 1.6 s
- Button label: PRESS AND HOLD, then UPDATING... while held
- Era is driven by h (not by scroll): h < 1 is era 1; h >= 1 is era 2; done or h >= 2 is era 3. Segment bar fills h's fractional part (24 cells); smooth bar width = same percentage
- TENSION: hold.tension eases to 1 while holding (rate 4/s) and back to 0 (rate 9/s). While tension > 0: the UI layer leans toward the pointer (transform-origin at the pointer position inside the layer; scale(1 + .045 t, 1 + .06 t)), jitters up to 3 px when t > .3, and on non-coarse pointers adds filter saturate(1 + .4 t) brightness(1 + .12 t) (NOT on phones: too costly). The 3D camera FOV also tightens 6% * t and trembles ~.004 m * t. Zero tension under reduced motion
- Cursor-following pill: a small pill that trails the pointer on a spring (k = 1 - exp(-dt * 16), offset +26, +14) and tilts with its speed (rotateY from vx * .03 max 28 deg, rotateX from -vy * .03 max 22, rotateZ vx * .008 max 10), scales .8 to 1 when shown. While the hold is waiting and the pointer is over the layer, the pill stays visible with "press and hold". Desktop only (hidden on touch)

### 6d. Gates: refusing to scroll
- limit(pv) = min(pv, firstUnfinishedGate.at). While a gate waits: wheel (down) is preventDefault'ed if scrollY + delta > (gate.at + 3)/100 * innerHeight, and the page is snapped to that limit; touchmove (finger up) is preventDefault'ed when scrollY >= limit - 2; ArrowDown / PageDown / Space are prevented when the target is the body. Do this at the INPUT, not by undoing scroll afterwards (the undo flashes one frame). Also, in the frame loop, if waiting and not pressing and the raw position > at + 3, scrollTo it back
- Any gesture while waiting counts as "wants to go on": nudge() (throttled 450 ms): the card bounces (keyframes: up 26 px, down 8, settle, .45 s), a hint pill reads "press and hold" (hold gate) or "press the button" (dialogs), the dialog's button pulses (a ring that expands and fades). The hint stays 4 s
- reset() re-arms everything (used by the replay button). skipAll() marks every gate done (used by "Skip the story")

### 6e. Dialogs (3, one at a time)
- Frosted dark glass cards, 1388 px design width scaled to the panel (--s .8333; portrait phones 640 px wide and --s 1), radii 20/20/60/60, a 68 px header bar with a hairline, a path-like label ("name/id") and 3 dots, a centred eyebrow, a giant display title (200 px; error 170; success 128), and a full-width gradient button (116 px tall, caps, 500 weight) with a label and an SVG arrow
- Sequence: 1) STATEMENT (eyebrow + 2-line title + button "Continue"), 2) ERROR (red theme; eyebrow "Error: sketch_not_found"; title; button "Try again" with a redo icon), 3) SUCCESS (green theme, dark label text; eyebrow, 3-line title; button "Done" with a down arrow)
- On OS era 3 there is nothing left to update, so the statement dialog appears straight away
- Only one is visible; the others are `inert`. Announce the visible title in an aria-live region
- ARMING: when a dialog appears, its button "charges": a dark overlay (inset 0, scaleX 1 to 0 over .75 s; .25 s under reduced motion) sweeps off, and clicks are ignored until armed (armedAt timestamp). Prevents accidental double-clicks
- On press: SFX (next / error / done), the button shows .is-pressing for 260 ms (a ring that expands), the dialog gets .sent (scale .97, opacity .55), and the gate finishes: done = true, smooth-scroll to gate.next. The ERROR dialog adds .glitch to the layer for 1.1 s (the wallpaper shakes and hue-shifts, steps(2) x2)

## 8. AUDIO (music.js)
- Sound is ON by default but cannot start before the first gesture. It starts when the cable connects. The header Sound pill shows four animated bars while on (heights 3 to 12 px, staggered delays) and strikes the label through when off; the choice persists in localStorage
- The ambient loop fades in over 2.5 s (via Web Audio gain, target ~0.32), pauses while the tab is hidden. SFX buffers decode early (on the first pointerdown). SFX volume ~0.3, quieter than the music
- Riser: a stretched build-up that follows the hold. start(frac) begins at the current fraction of the buffer with a 0.12 s fade-in to ~0.42; stop(sec) fades out
- iOS: set navigator.audioSession.type = "playback"; route the audio element through a Web Audio GainNode (iOS ignores audio.volume); unlock on the first touchstart / pointerdown / touchend / pointerup / click / keydown (capture phase, passive): resume the context, start the music if wanted, otherwise play it silently once (gain 0) so it can start later from anywhere. Finger-DOWN counts as permission, the lift after a drag does not

## 9. PERFORMANCE AND ADAPTIVE QUALITY
- Quality tiers: 2 = AO + bloom, 1 = bloom only, 0 = minimal. Start at 2 on desktop with a strong GPU; start at 1 on phones and weak GPUs (detect UNMASKED_RENDERER_WEBGL: Intel / UHD / Iris / Mali / Adreno / PowerVR / Apple GPU count as weak unless NVIDIA / Radeon RX / GeForce)
- Dynamic resolution: pixel ratio starts at min(devicePixelRatio, 1.5) on desktop (weak GPU: 0.75). On phones use a fixed pixel budget: min(dpr, 2, sqrt(650000 / (innerWidth * innerHeight))) and never go below 1x. If the average frame time exceeds ~21 ms for 45 frames: first drop AO, then scale the DPR by 0.8 (min 0.5 on desktop), then drop bloom. After 4 s of smooth frames (< 17.5 ms), step the DPR back up x1.2 (max 3 times). Apply a scale change at the START of the next frame, right before drawing, to avoid a cleared frame. Skip adaptation when ?q or ?dpr is set or the tab is hidden
- Phones: skip GTAO, use the light GLB variant, no backdrop-filter anywhere in the story layer
- Compile shaders, upload textures and settle the first frames BEHIND the loader. Never compile on first use
- On resize: re-size renderer, composer, film res; re-layout CLOSE and CLOSE_M; re-size the wall text from the wide shot; then re-render immediately (a resize clears the canvas). Ignore phone toolbar resizes (only react when the CANVAS size changes)
